## ⚠️ Two blockers only a human can clear

### 1. You need a domain you own

Resend — and every transactional provider — requires DNS verification of the sending
domain (SPF, DKIM, DMARC). **Nobody can add DNS records to gmail.com**, so
`ohy.okuhle@gmail.com` cannot be a *sending* address. It works perfectly as the
*recipient* of owner alerts.

```
FROM (sending):    orders@okuhle.co.za    ← needs a domain you own
TO (owner alerts): ohy.okuhle@gmail.com   ← works as-is, no setup
```

If the domain isn't bought, **this whole build is blocked**. ~R100–200/year for a .co.za
from Domains.co.za, Xneelo or Afrihost. Point it at Netlify.

### 2. The API key must be created by you, in a browser

API keys are generated by a logged-in human in the Resend dashboard. No agent can do it.
The code that consumes the key is written and tested; the key itself is yours to create.

**Give it "Sending access" only** — not full access. Least privilege.

**The key goes in Netlify environment variables ONLY.** Never in the code, never in a
commit. If it ever lands in a commit, **revoke it in Resend and generate a new one** —
deleting the line is not enough, because it stays in git history.

## Manual setup (~30 min)

1. Buy the domain, point it at Netlify.
2. Sign up at resend.com (use `ohy.okuhle@gmail.com` as the account email).
3. Resend → Domains → Add Domain. Add **every** DNS record it gives you at your
   registrar. Wait for all of them to read "Verified".
4. Resend → API Keys → Create, permission "Sending access". **Copy it immediately** —
   Resend shows it once.
5. Resend → Audiences → Create → "Okuhle List". Copy the Audience ID.
6. Netlify → Site settings → Environment variables:

```
RESEND_API_KEY      = re_xxxxxxxxxxxxx
RESEND_AUDIENCE_ID  = xxxxxxxx-xxxx-xxxx
FROM_EMAIL          = orders@okuhle.co.za
FROM_NAME            = OHY Okuhle
OWNER_EMAIL         = ohy.okuhle@gmail.com
```

Until step 6 is done, every email logs to the console instead of sending. Nothing
breaks; nothing arrives either.

## ⚠️ The Black Friday ceiling

**Resend free tier: 100 emails per DAY.** Each order sends two (customer + owner), so
the free tier caps at **~50 orders/day**.

If 27 November goes well, that cap is hit and confirmations stop — customers pay and
hear nothing, which produces exactly the WhatsApp support flood this system exists to
prevent.

Built in as a result:
- Every send is counted and logged
- At **80 sends** the owner gets an email warning (verified: fires at exactly 80, once)
- A 429 (rate limit) **queues** the email rather than dropping it
- A failed email **never** affects the order — payment state and email state are
  independent, and the order is recorded before any email is attempted

**Action: upgrade Resend before 27 November, or accept ~50 orders/day.**

The in-process send counter undercounts across serverless instances — it's a smoke
alarm, not an accountant. The authoritative number is the Resend dashboard.

## Okuhle+ — R299 for the year

One payment, twelve months. **Not a subscription** — nothing recurs, nothing
auto-charges. The member renews deliberately after a reminder.

| Rule | Value |
|---|---|
| Price | R299/year (R25/month equivalent) |
| Discount | 12% |
| Free delivery | orders **from R500** (not unlimited) |
| Early access | 48 hours |
| Member colourways | 4/year |
| Renewal reminder | 14 days before expiry |

### The honest economics

At 12%, a member needs about **R2,492 of orders in a year** for the discount alone to
repay R299. At 3–4 items a year that's roughly break-even. This is why the page leads
with access — member-only pieces, guaranteed allocation, the 48-hour head start — and
puts the discount last. The FAQ says so outright: *"If you just want money off, don't
join."*

**Watch this:** 12% + free delivery over R500 means a *heavy* member is unprofitable. A
R540 order costs ~R65 discount + ~R70 delivery = R135. Four of those exceeds the R299
fee. The R500 floor limits the damage but doesn't remove it. Revisit once cost per
garment is known.

Unlimited free delivery was **not** built, deliberately — at ~R70/shipment it costs more
than the whole fee after four orders.

## Still blocked on accounts

Membership needs `user_id`, so these are written as logic and tests but cannot run
end-to-end until auth exists:

- Member numbering (sequential, permanent, never reused)
- Membership records and expiry
- Member pricing applied at checkout
- `/members` public list, member badges
- Renewal reminder job (needs a scheduler + durable store)

The PayFast membership checkout is also not wired, for the same reason as product
checkout: **no durable order store**. `/okuhle-plus` currently routes joins through
WhatsApp, which is honest and works today.

## POPIA

- Marketing consent is a **separate, unticked** checkbox, never bundled with anything.
  Verified in a browser: `checked by default: false`.
- `/api/subscribe` **refuses** a request without explicit `marketingConsent: true` —
  absence is never treated as consent.
- Only opt-ins reach the Resend audience.
- Transactional emails carry no promotional content — smuggling marketing into an order
  confirmation would reclassify it and require consent it doesn't have.
- Opt-outs must be honoured from any channel, WhatsApp included.
